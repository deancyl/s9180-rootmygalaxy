## 2. 归因结论（三分类）

### A. 模块直接相关 → **不是当前主因，但存在一条应修复的真实风险路径**

- **当前排除**：FR-RN1 旁路 + 零残留；音频/VAD/名单线程 nice 全 0；cpu_scan 正常。
- **历史风险**：`mt_lib.sh` 启动风暴窗口（480s）内 `renice_tree "$pid" +5` 作用于**整个进程的所有线程**（L450），豁免仅「白名单 / 前台焦点 / `oom_score_adj<=200` 前台服务 / Launcher」。而 `WHITELIST_PKGS`（L89）**不含 `com.rayneo.venus.pub`**；RayNeo 当前 adj=651（后台态），一旦在风暴窗口内冷启动就可能命中。实测 `deprioritize_rayneo=1` 证实该路径已被触发过。窗口结束会批量还原，但历史存在 `restore_skipped_changed`（第三方改动则跳过还原）的残留风险。
- **影响**：整进程 nice+5 会同时压低 AudioThread / ASR Dart isolate / 网络回调线程，在实时语音场景下足以造成缓冲欠载与识别错误。
- **修复方向（零风险，可并入 v1.13.13）**：把 `com.rayneo.venus.pub` 加入削峰豁免白名单；更精准的做法是对「持有录音/语音前台服务或 `AudioRecord` 活跃」的进程豁免**整进程**削峰（只约束其非音频线程）。

### B. 系统环境 → **当前最可能的加重因素**

持续灾难换页 + CPU PSI 20% 会让实时音频采集线程得不到及时调度，音频缓冲欠载后 ASR 前端拿到的片段不完整，表现为漏字、串音、转写成别的句子。11-06 凌晨至 08:52 至少 7 次换页风暴，与用户 09:08 的观察时间接近。

### C. RayNeo App / 网络侧 → **「语义级识别错误」更直接的指向**

- 唤醒正常、焦点正常 → 麦克风与唤醒链路无故障；
- 「11月9日会下雨吗」变成别的内容属于 **ASR 文本结果错误**，典型成因为云端 ASR 超时后降级到本地小模型、或请求被 DNS/代理拖慢后返回异常结果。当前代理核心 mihomo / CMFA 在运行、AGH 在跑且集成 unpatched，活动 profile 缺 IP 兜底 + 境外 DoH 走节点，与「ASR 请求绕远路」高度吻合（与今早 09:09 代理流量取证的独立结论交叉一致）；
- 另外 VAD=1 表示**全天智记持续在录音**，唤醒语音助理后可能是 App 内双路录音/音频源争用（属 RayNeo 内部实现，非模块）。

> 诚实说明：现有 logcat 近 8000 行未抓到 RayNeo 私有 ASR 结果/错误 tag，C 类为**基于链路证据的高可信推断，非直接实证**；需复现瞬间定向采集才能定论。
