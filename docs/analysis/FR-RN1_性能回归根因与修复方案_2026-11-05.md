| 指标 | A（flag ABSENT） | B（flag PRESENT） |

**机制**：`rayneo_governor` 挂在 `scan_cpu_rogue` 尾部（在 `cpu_scan` 计时区间内）。移除 flag 后每轮必跑 `rayneo_memo_active()`，它遍历 RayNeo 的 ~181–221 个线程，对每个线程执行 `$(cat "$t/comm")` —— **每次都是一次 fork**。在换页风暴（当日 20–98 万 majflt/60s）与内存压力下 fork 成本暴涨，累计 1.7–13s/轮；旁路时首行 `return 0`，零开销，故瞬间回落。

这是 v1.13.12 引入 P1-5 门控时的**实现缺陷**（逻辑正确、探针开销未评估），与 v1.13.11 的降权逻辑无关。

## 4. 修复方案（三档，推荐 A）

### 方案 A（推荐）：`cat` → mksh 内建 `read`，零 fork

```sh
rayneo_memo_active() {
  for _t in /proc/$rpid/task/*; do
    [ -r "$_t/comm" ] || continue
    IFS= read -r _rn_comm < "$_t/comm" 2>/dev/null || continue
    case "$_rn_comm" in "$RAYNEO_MEMO_THREAD"*) return 0 ;; esac
  done
  return 1
}
```
- 同时把降权循环的 `comm=$(cat "$t/comm")` 改为同款内建 read。
- **依据**：v1.13.2 耗电治理已用同一模式把 PSI 读取改为 mksh `read` 零 fork（当时 CPU 7.9h/日 → 7.5% 单核），属已验证的既有范式。
- **风险**：极低；仅替换读取方式，判定语义、名单、铁律、Tgid 校验全部不变。
- **验收**：移除 flag 后 `cpu_scan done_ms < 300ms`（连续 5 轮）；memo 激活时零 demote；memo 未激活且 adj>300 时正常降权；单元测试覆盖「有/无 VAD、comm 含空格、线程换代」。

### 方案 B（二期）：VAD tid 缓存
把命中的 VAD tid 落 `$RUN/rayneo_vad.tid`，下轮先读该文件 + 内建 read 校验该 tid 的 comm（附 Tgid 归属校验），失配才全量扫 → 稳态每轮 1 次内建 read。风险：缓存 tid 复用需防护（P0-1 已有模式可复用）；复杂度略高。建议 A 稳定后再评估。

### 方案 C（架构，暂不推荐）
由 fluency_shield（5s tick、已有 RayNeo pid 基线）落 memo 激活状态文件，cpu_guard 只读该文件 → 彻底免除遍历。跨进程协作需评估一致性与失败回退，收益有限，不推荐本轮。
