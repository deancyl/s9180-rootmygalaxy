# MemTonic v1.13.16 开发与部署方案（2026-11-08）

> 前置：设备当前 adb 离线（`no devices/emulators found`），阶段 A 的剩余审计与后续部署需设备恢复后进行。本方案基于 11-08 已完成的两轮审计（628 堆快照 / 19 天、37.3h 归档日志、NoActive 注入验证、v1.13.15 部署验收）编写。

## 三、实现思路

**原则**：每个阶段独立可回滚；先只读、再脚本、最后 WebUI；任何改动都必须有"改动前备份 + 失败自动恢复 + 独立旁路验证"三件套。

### 阶段 A：只读审计（0 风险，不改设备）

- **A1 还原完整性**：逐行读 `uninstall.sh` 与 `memtonic.sh stop` 分支，核对"每个 `*_on()` 都有配对的 `*_off()` 且被 stop/退出路径调用"；核对是否有 `mount -o rw`、分区写入、`knox` 属性触碰（预期为 0，需证据）。
- **A2 冲突矩阵**：对 8 个 KernelSU 模块 + 2 个 LSPosed 模块，检索是否触碰 `vm.*`、`/dev/cpuset`、`max_cached_processes`、`lmkd`、`renice` 同一目标；形成"谁管什么"的职责表，冲突时以**不接管他人职责**为原则。
- **A3 交集验证**：取 NoActive 当前冻结集（约 102 进程）与 MemTonic 护航/提权集（近 12 条日志目标），确认无重叠；若有重叠，改为"只对前台/可见进程提权"。
- **A4 变砖风险清单**：列出所有写操作点（`/proc/sys/vm/drop_caches`、`renice`、`taskset`、`chown`、`touch`），逐个标注可回滚性与影响面。

### 阶段 B：脚本收敛（需一次守护重启）

- **B1 FR-RN1 零 fork（分 3 步，每步独立验收）**
  - B1a：`Tgid` 归属校验改内建读（`IFS= read` 逐行解析 `/proc/<tid>/status`，去掉 `awk`）
  - B1b：`nice_of` 改内建读 `/proc/<tid>/stat`（`set --` 切分取第 19 字段）
  - B1c：eyewear 探针 `cat oom_score_adj` 改 `IFS= read`
  - 每步后跑 5 轮 `cpu_scan`，要求 `<300ms`；任一步失败即停在该步并回滚
  - **仍是旁路态**：只有三步全绿才移除 flag，否则保持 PRESENT（宁可不用，不可拖慢）
- **B2 `drop_caches` 埋点校准**：首次触发时记录前后 `MemFree`、`pgsteal_kswapd`；若 60s 内收益 <200MB，降频至 30min 或改 `echo 1`
- **B3 护航续期（保守版）**：`sleep 15` → 分段 `sleep 5 × 最多 6 次`，每段后重读 mem PSI，回落到 <12% 提前退出；上限 30s（防止阻塞其他哨兵太久）；冷却 60s → 45s
- **B4 快照历史清理**：一次性 `find -mtime +7 -delete`（保留最近 7 天，约 170 个）
- **B5 A-1 门控补强**：增加第三条触发条件——堆历史斜率（连续 3 点上涨 >15MB/次）也算"值得探测"，防 RSS 稳定漏探

### 阶段 C：WebUI 收敛（单文件，零重启）

- **C1 首屏压缩**：状态胶囊（保护/权限/版本）+ 安全条 + **健康分卡**（低/中/高 + 一句人话）+ 3 个数字（可用内存 / 堆 / swap）+ 刷新。目标首屏 ≤2 屏（390px）。
- **C2 整机内存卡**：`MemFree / swap used / CPU PSI / compact 失败率`，与堆并列；解决"堆 223MB 正常但 free 79MB"的误判。
- **C3 OOM 风险评分**：堆水位 × swap 使用 × PSI mem × compact 失败率 → 低/中/高，文案直白（"今晚可能崩"级别）。
- **C4 NoActive 健康检查**：读 `/data/adb/lspd/log/verbose_*.log` 最后一条 `NoActive运行环境正常` 的时间，>6h 未更新则在面板提示。
- **C5 折叠区 6 → 4**：合并"运行状态与限制"+"这个模块不会做什么"；"内存细节"并入"保护记录"。
- **C6 契约守护**：保留全部 DOM id、5 次 execCmd、11 段解析、`AUTO_SEC=30`、四按钮；单测从 241 项扩到 ≥260 项（新增 C2/C3/C4 断言）。

### 阶段 D：验证与回归

- D1 单测 ≥260 全绿；`sh -n` 全过；HTML id 唯一/标签平衡/单 script 块
- D2 部署 7 步：staging/设备 md5 双检 → 备份 `scripts.bak-1316` / `webroot.bak-1316` → stop → 原子替换 → 设备 md5 复检 → 单次重启 → 特性验收（失败自动回滚）
- D3 独立旁路：pull 读回逐字节 `cmp` + 对读回文件独立跑逻辑断言（不依赖本地源）
- D4 实机观察 30–60 分钟：`cpu_scan` 分布、日志增长率、快照增量、四进程 CPU/RSS、PSI、free/swap
- D5 冲突复检：NoActive 冻结数与注入时间、护航目标是否落在冻结集
- D6 回滚演练：`cp -p` 备份回 + `service.sh`，确认恢复后 `cpu_scan` 与版本正确

## 四、关键风险与缓解

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | FR-RN1 三步中任一步验收失败 | **中**（历史上失败过一次） | 中 | 每步独立备份+回滚；失败即停在旁路态，不影响现有功能 |
| R2 | `drop_caches` 造成 IO 抖动 | 中 | 低-中 | 限流 10min/1h≤6；埋点量化；收益 <200MB 即降频或改 `echo 1` |
| R3 | 护航分段延长阻塞其他哨兵 | 中 | 中 | 上限 30s + 每 5s 检查退出；相机/BT 哨兵延迟从 15s→30s（可接受） |
| R4 | WebUI 再引入回归（如上次 CSS 椭圆） | 中 | 中 | 保留全部 id/契约 + 241→260 项单测 + 390px 四段实渲染逐一核对 |
| R5 | 与 NoActive/OneUIX/scene/rekernel 参数冲突 | 低-中 | 中 | A2 矩阵先查；冲突时让出职责；只对前台/可见进程提权 |
| R6 | 部署中 adb 掉线 | **高（已发生）** | 中 | 脚本 `exec > log`，恢复后读日志续判；备份在模块目录，可离线回滚 |
| R7 | 完整重启导致临时 root 丢失 | 中 | 高（需重新 exploit） | 模块不碰 boot/分区；重启由用户触发；提供恢复步骤 |

**底线（不因任何优化而放松）**：不杀进程、不冻结、不动 zram、不持久改内核参数、不刷写分区、不代执行重启、nice 只提不降、前台/相机/蓝牙/微信不干预。

## 五、验证方法（对应每一项目标）

| 目标 | 验证手段 | 通过标准 |
|---|---|---|
| 安全稳定 | 部署 7 步 + 60min 观察 + 回滚演练 | 无 fallback 触发；四守护 4/4；uptime 连续；回滚后版本与性能均正确 |
| 绝不导致变砖 | A1 静态审计 + 写操作清单复核 | 无分区/boot 写入、无 `mount -o rw`、无 Knox 属性写；`uninstall.sh` 覆盖所有 `*_on()` |
| 省电低功耗 | `/proc/<pid>/stat` utime+stime ÷ uptime ÷ 核数；RSS | 四进程合计 <1.5% 单核；RSS <20MB；无新增周期任务 |
| 不与其他模块冲突 | A2 冲突矩阵 + D5 复检 | 同一参数无双重设置；护航目标不在 NoActive 冻结集；无模块互删/互改 |
| 运行高效 | `cpu_scan` 分布（p50/p90/max）；日志行/小时；快照/天 | p50 <250ms；无 >1000ms（除首轮/部署）；日志 <15 行/h；快照 ≤24/天 |
| 与 NoActive 配合 | 冻结数、注入时间、护航目标校验 | 冻结 80–150；注入 <6h；护航目标非 frozen |
| WebUI 简洁健全 | 单测 + 390px 四段渲染 + 首屏屏数 | ≥260 全绿；首屏 ≤2 屏；无溢出/重叠；ⓘ 可点可关 |
| 遗留清零 | 12 项逐项验收表 | P0 全部闭环或明确"不修理由"；P1 ≥5 项闭环；P2 记录在案 |

## 六、执行顺序与回滚点

```
A（只读审计，无回滚需求）
  └→ B1a → 验收 → B1b → 验收 → B1c → 验收 →（全绿才移除旁路 flag）
  └→ B2/B3/B4/B5 合并为一次部署（备份 scripts.bak-1316）
  └→ C（WebUI 单文件热替换，备份 webroot.bak-1316）
  └→ D（验证 + 回滚演练）
```

每阶段的回滚命令在部署日志末尾自动打印，且备份常驻模块目录。

## 七、待设备恢复后立即执行的三件事

1. `adb devices` 确认在线；若手机已完整重启，先重新跑一次 exploit 恢复临时 root，再 `sh service.sh` 拉起守护
2. 完成 A2/A3 审计（约 5 分钟），输出冲突矩阵
3. 按 B1a → B1b → B1c 顺序改 FR-RN1，每步验收后再继续
