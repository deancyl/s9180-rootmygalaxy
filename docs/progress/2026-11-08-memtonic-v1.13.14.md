# MemTonic v1.13.14：FR-SS 六项改造 + WebUI 时效/交互修复（2026-11-08）

## 定位

11-07 23:03:25 发生**第四起同型软重启**：`OutOfMemoryError: HeapFull, 501MB was used` @ `Watchdog`（前三起为 10-22 / 10-25 / 11-05，496–501MB）。取证发现关键事实：**`ss_heap_relief` 当日尝试 22 次全部失败，`ss_heap_trim` 全天 0 次成功**——唯一泄压手段 `am send-trim-memory` 走 binder 到 system_server，堆濒死时必然不可达，模块实际只具备「记录 + 建议」。

本轮据此做两件事：**① FR-SS 六项改造**（模块版本升 `v1.13.14 / vc54`，需一次守护重启）；**② WebUI 三项修复**（告警时效化、弹层兜底关闭、禁用原因说明）加一处 CSS 误伤修复（零守护重启热替换）。

## 变更内容

### FR-SS 六项（`scripts/mt_lib.sh`）

1. **内核路径兜底 `ss_drop_caches`**：`am` 全部尝试失败后写 `/proc/sys/vm/drop_caches`（不经过 framework，确定可达）；限流 10 分钟 1 次、1 小时≤6 次；作用域为 page cache / dentry / inode 等可回收 slab，不触碰 Java 堆、不动 zram、不改持久内核参数。
2. **`am` 单轮重试 ×3**（立即 / +4s / +8s，总阻塞 ≤8s），失败必走内核兜底；复测间隔 120s→30s。
3. **阈值前移**：450MB 完整泄压链、460MB GC 加速、470MB 告警、480MB 极限压制、430MB 预备态；496MB 仅作 OOM 参考线。
4. **GC 加速加强**：nice -10→**-15** + 尝试 `taskset` 绑大核（cpu5-7，失败静默降级）；还原用 delta 法 + `taskset -p ff` 恢复亲和。
5. **趋势判定**：`ss_heap_recovered` 由「单点 <450MB」改为「连续 3 次 <430MB 才撤销」，并落 `act=ss_heap_holding` 供观察。
6. **抑制态转极限压制**：检测 `reboot_suppressed.flag` 时探测加密到 60s，每轮叠加 am 重试 + drop_caches + GC 提权，落 `ss_heap_extreme.flag`。
   另：`gc_boost_on` 的 comm 读取改 `IFS= read`（零 fork 补全）。

### WebUI（`webroot/index.html`）

- **时效化**：数据源为每个 flag 追加 `_mtime`（`stat -c %Y`），前端 `parseFlag/agoText/isFresh` 按 `2h / 24h` 分级——超 24h 的历史提示降级进「技术细节」，不再永久占据首屏告警位（11-06 的 `boot_context.flag` 一直存在，旧实现「存在即告警」）。
- **弹层兜底**：ⓘ 弹层改为「点弹层外任意处即关闭」（原实现只认遮罩元素本身，卡住后整页按钮都像没反应）。
- **禁用原因**：守护运行时「开启保护」的说明行改写为「保护正在运行，这个按钮已禁用（无需重复开启）」。
- **CSS 误伤修复（关键）**：`.quick button{width:100%}` / `.oprow button{width:100%}` / `.advbtns button{...}` 三个宽泛选择器**误伤了圆形 ⓘ 按钮**（特异性高于 `.ib`），实机表现为「按钮被拉成横向椭圆 + 点击落在错误区域」。全部改为子选择器 `.quick>button` / `.oprow>button` / `.advbtns .oprow>button`。
- 阈值/刻度同步为新链：`450 清理 / 460 加速 / 470 告警 / 496 危险`。

## 已知问题（诚实标注）

- **system_server 堆泄漏发生在框架内部，用户态手段无法根治，只能延后与缓解。** 本次改造把「几乎无干预」变成「有 30–60 分钟窗口 + 一条可达泄压路径」，但**不能承诺不再发生**。真正根治需要系统侧行为改变（深夜 AOD 人脸 / face-service 借相机），属用户可选设置范畴。
- `drop_caches` 只回收页缓存与可回收 slab，不解决 Java 堆本身；其价值是在 binder 不可达时提供唯一的物理页释放路径。
- 部署时 `rb_enabling=1`（存在 staged rollback），因此重启系统仍被禁止；守护重启不影响该状态。
- KernelSU Manager 可能缓存旧 HTML，需关闭并重新打开模块页面。
