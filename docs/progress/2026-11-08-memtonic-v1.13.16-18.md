# MemTonic v1.13.16–18：审计落地（还原完整性 / FR-RN1 首次启用 / WebUI 收敛）

## 定位

承接 11-08 的近 5 次部署审计（628 堆快照 / 19 天 + 37.3h 日志），按 A（只读审计）→ B（脚本）→ C（WebUI）→ D（验证）四阶段执行。本轮最重要的成果是 **FR-RN1 雷鸟治理首次成功启用**（v1.13.13 曾验收 0/5 自动回滚）。

## A 阶段审计结论（只读，未改设备）

| 项 | 结论 |
|---|---|
| 还原完整性 | **发现缺口**：`stop`/`uninstall` 用 `kill -9` 跳过子进程清场，`gc_boost` 提权、相机 provider 亲和、核亲和约束三类会残留 |
| 模块冲突 | 8 个 KernelSU + 2 个 LSPosed 模块，其文件均未触碰 `vm.*` / `/dev/cpuset` / `max_cached_processes`；`swappiness=145`、`max_cached=1030` 经 `settings/device_config/props` 排除后确认为三星 ROM 定制 |
| NoActive 交集 | 冻结集（108 进程）与护航集无实质冲突：B站虽在冻结集，但冻结发生在后台、护航发生在前台，时间互斥 |
| 写操作点 | 仅 `drop_caches` / `renice` / `taskset` / cpuset 迁移 / 文件读写，无分区、无 boot、无 mount rw |

## 变更

### v1.13.16（B0 / B1 / B5）

- **B0**：`stop` 与 `uninstall` 显式补 `gc_boost_off`、`camera_affinity_off`，并按 `affinity_constrained.lst` 逐条写回原 cpuset。
- **B1**：`nice_of` 改内建读 `/proc/<pid>/stat`（原 awk，renice 循环里几十次/轮）；`is_foreground_service`、两处 Tgid 校验、眼镜探针、两处 `pidof|awk` 全部零 fork 化。
- **B5**：探测门控增加"单 tick RSS 涨 >10MB"条件，覆盖"堆缓涨但 ΔRSS<30MB"的漏探。

### v1.13.17（B1c：真正的瓶颈）

v1.13.16 验收仍未通过（1460–3840ms），**根因不是读而是写**：降权循环对 181–221 个线程逐个 `renice`（每次一个 fork）+ 每 tid 一次 `grep -q` 查重 + 每线程一条日志 ≈ **600 fork/轮**。

- 实机验证 `renice -n N -p pid1 pid2 ...` 支持多 PID；
- 按 nice 分桶（绝大多数为 0）→ 一次调用覆盖几乎全部；
- 查重改内存集合、日志改每轮一条。

**结果：FR-RN1 首次通过验收并正式启用**——`cpu_scan` 从 1770–13010ms（v1.13.13）→ 1460–3840ms（v1.13.16）→ **340–730ms**。

### v1.13.18（C 阶段：WebUI 收敛）

- **健康分首屏**：可用内存 / 堆 / swap / mem PSI / CPU PSI 综合出 0–100 分 + 一句人话，替代原来三张只讲堆的指标卡（解决"堆 249MB 正常但物理内存 99% 用满"的误判）。
- **整机内存字段**：`collect_stats` 新增 `swap_total_kb` / `swap_free_kb` / `cpu_psi_s10`（零 fork 读 `/proc/meminfo` 与 `/proc/pressure/cpu`）。
- **折叠区 6→4**：「内存与保护」「运行状态与限制」（并入安全边界）「最近记录」「更多操作」。
- 契约不变：5 次 `execCmd`、11 段解析、全部 DOM id、`AUTO_SEC=30`、四按钮。

## 验证

- 单测 **266/266**（253 + 13 项 C 阶段断言）。
- 部署 8 步全绿（staging/设备双 md5 → 备份 → stop → 原子替换 → md5 复检 → 单次重启 → 特性验收 → 观察）。
- **D 阶段实测**：v1.13.18/vc58；四守护存活；模块总 RSS **12.8MB**、CPU **1.5% 单核**；`cpu_scan` 12 轮 **340–730ms** 无超标；FR-RN1 在役（161 线程中 32 个降权）；快照 **628→257**（7 天清理生效）；NoActive frozen 108；`swappiness`/`max_cached` 未变。
- 390px 本地渲染确认健康分卡、四数字 2×2、堆刻度与 PSI 条、4 折叠均正常。

## 已知问题（诚实标注）

- **`cpu_scan` 340–730ms 未达 300ms 目标**：瓶颈已定位为 `rayneo_memo_active` 与降权循环**各遍历 161 个线程一次**（322 次 /proc 读取），下轮可合并为单次遍历。
- **`drop_caches` 仍未实弹触发**（堆未达 450MB）。
- 健康分是相对评估，阈值按本机 12GB+12GB swap 实测分布定，非绝对指标。
- 整机压力（swap 6.8GB、CPU PSI 20%、碎片化）属容量级问题，本轮未动系统设置。
- NoActive 健康检查未做（读 1.2MB LSPosed 日志成本高于收益）。
