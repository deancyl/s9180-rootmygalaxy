# MemTonic v1.13.19 ~ v1.13.20 联合开发与发布进展报告（2026-11-09）

## 一、版本演进背景与双版本定位

在 2026-11-09 的密集迭代中，针对外部审计反馈与深层静态审查，MemTonic 连续完成了两代关键演进：

1. **v1.13.19 (vc59)**：外部审计 9 项确定性缺陷集中修复，**不改动任何调度阈值与功能语义**，聚焦正确性（Tgid Tab 拆分、cpuset 全线程组迁移、卸载与启动生命周期完整性、renice 增量语义、内存余量预测刷新与零 fork 降本）。
2. **v1.13.20 (vc60)**：外部复核收尾热修（`RAYNEO_PKG` 作用域 P0、`KSU_MODULE` 环境变量补齐、消除启动日志硬编码）+ **攻克历史遗留 P0（FR-4 CPU 毒瘤检测全面恢复与全链路零 fork 极速重构）**。

- **目标设备**：Samsung Galaxy S23 Ultra（SM-S9180，dm3q，One UI 8 / Android 16，内核 5.15.189-android13-8-33413713-abS9180ZHS8FZG1）

## 二、关键缺陷根因剖析与修复工程

### 1. v1.13.19 外部审计九项缺陷收口
- **P0-1 Tgid Tab 分隔符**（`cpu_guard.sh`）：`/proc/<tid>/status` 的 Tgid 行是 `Tgid:\t<pid>`，显式空格 `IFS=' '` 不拆 Tab，导致 `_tg` 恒空，`rayneo_restore_all` 100% 返回 `restored=0`，且死条目清理每轮清空 `RN_STATE` 导致重复降权。改默认 IFS，写入多少还原多少（实测 3/3 还原）。
- **P0-2 cpuset 只迁主线程**（`cpu_guard.sh`）：`/dev/cpuset/*/tasks` 按线程写入，写 tgid 只迁移了主线程，工作子线程滞留原 cpuset。全面升级为 `cgroup.procs` 按线程组整组迁移。
- **P0-3 卸载不终止子进程**（`uninstall.sh`）：原卸载脚本缺少 pkill 且优先删除了 `run/` 目录，导致子守护成孤儿且清单丢失无法还原。补全 4 个 pid 文件检测与 4 条 pkill，清场动作移至目录清理之前。
- **P0-4 service.sh 幂等漏洞**：主进程死而子守护存活时拉起会产生双实例，改为异常终止先清场再拉起。
- **P1-1 renice 增量语义误用**：Android toybox 的 `renice -n` 为相对增量，原 `-n 10` 与 `-n -15` 会在现有 nice 上无限叠加。改为 delta 增量换算，并补全 `> -15` 保护下限。
- **P1-2 护盾提权未落盘**：`fluency_shield.sh` 在 15s 护盾窗口内若遭遇 kill -9 会导致 SurfaceFlinger 与前台线程停留在 -15。新增 `run/shield_fg.bak` 持久化，启动自愈/stop/uninstall 统一还原。
- **P1-3 mem_forecast 旧值冻结**：预测态仅在首次落盘，导致几小时后的历史低可用内存仍触发亮屏压实。改为动态刷新 + 读实时可用内存 + 亮屏 PSI 门槛。
- **系统降本与健壮性**：`am` 增设 `timeout 2`；`dumpsys rollback` 单次采集 60s 复用；`collect_stats` 14 次 grep 合并为单次 awk；`is_frozen_pid` 跳过 NoActive 冻结进程；息屏降频采样。

### 2. v1.13.20 外部复核收尾热修
- **P0 RAYNEO_PKG 作用域修复**（`mt_lib.sh`）：`RAYNEO_PKG="com.rayneo.venus.pub"` 原仅在 `cpu_guard.sh` 中定义。移至 `mt_lib.sh` 顶部全局常量区，修复 `restore_all_on_exit` 无法读取雷鸟 PID 导致 stop/uninstall 100% 跳过雷鸟线程还原的缺陷。
- **补齐 `KSU_MODULE` 环境变量**（`mt_lib.sh`）：`update_module_desc` 调用 `ksud module config set` 时显式注入 `KSU_MODULE=rmg_memtonic`，确保手动 Shell 与 WebUI 刷新时卡片覆盖层设置成功。
- **消除硬编码版本**：`memtonic.sh` 与 `fluency_shield.sh` 启动日志中的 `ver=1.13.18` 改为动态 `${MT_VERSION#v}`。
- **清理调试残留**：移除发布包内的 `.bak-1319-pre/`、`.t/` 目录与 `scripts/zz_probe.sh`。

### 3. v1.13.20 攻克历史遗留 P0：FR-4 毒瘤检测全面恢复与零 fork 攻坚
- **缺陷表现**：自 v1.9.9 以来，面板「毒瘤降权 0」并非系统没有毒瘤，而是 `snapshot_app_pids` 输出恒为空，导致 `scan_cpu_rogue` 外层循环从未执行，1349 次扫描 0 次干预。
- **根因分析**：
  1. `snapshot_app_pids` 的 awk 实现中，`FNR==1 { pid=""; uid=""; }` 从未给 `pid` 变量赋值。
  2. 依赖 `/proc/<pid>/status` 尾部的空行 `^$` 触发 print，但内核 status 文件末尾无空行。
- **修复与重构**：
  - `snapshot_app_pids` 改为：`FNR==1 { split(FILENAME, p, "/"); pid=p[3] }`，匹配到 `^Uid:` 且 `$2 >= 10000` 时输出 `pid` 并立即 `nextfile`，实测提取 96 个应用仅需 **80ms**。
  - 新增 `snapshot_app_ticks()`：单次 awk 扫描 `status`，仅对 `Uid >= 10000` 的应用通过 `getline` 提取 `stat` 的 `utime+stime`，消除逐进程调用 `cpu_ticks_of`（95 次 fork ≈ 1700ms 严重拥堵）的瓶颈，1 次 fork **90ms 批量完成**。
  - **核心辅助函数全链路零 fork 化**：
    - `pkg_of()`：由 `strings | head | cut`（3 次 fork ≈ 15ms）改用 `mksh` 内建 `IFS= read -r` 读 `/proc/<pid>/cmdline`，并于 `cpu_guard.sh` 中对 `_pkg_${pid}` 引入一级包名缓存，活跃进程无需每轮重复查询。
    - `is_in_top_app_cgroup()`：由 `$(cat /proc/$1/cpuset)` 改为内建 `read`，完全消除子 shell。
    - `nice_of()`：设置 `_nice_val` 变量，内部调用免除 `$(nice_of)` 命令替换子 shell。
    - `rayneo_governor` 死条目清洗：单次 awk 快速过滤替换原本每轮 2400+ 次 Shell read，清洗耗时由 **200ms 降至 5ms**。
