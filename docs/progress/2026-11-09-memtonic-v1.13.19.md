## 四、核心验收（对应用户要求的三项）

### 4.1 Tgid Tab 解析：真机新旧写法对比

在同一批真实线程上并排跑两种写法：

```
rpid=19615（com.rayneo.venus.pub）
tid=10343  old=[]  new=[19615]
tid=12128  old=[]  new=[19615]
tid=13551  old=[]  new=[19615]
tid=14495  old=[]  new=[19615]
```

- 旧写法（`IFS=' '`）：**4/4 全部返回空** → 完全复现审计结论
- 新写法（默认 IFS）：**4/4 正确解析出 19615**

### 4.2 `rayneo_restore` 的 `restored` 不再是 0

向 `RN_STATE` 写入 3 条**真实 tid**（nice 记录为当前值，还原动作是 `renice -n 0`，零副作用），
等一轮 60s 让真实代码路径（memo 门控 → `rayneo_restore_all`）去处理它：

```
11-09 14:48:43 L=A act=rayneo_restore restored=0   ← 旧版
11-09 14:51:47 L=A act=rayneo_restore restored=0   ← 旧版
11-09 15:57:56 L=A act=rayneo_restore restored=3   ← v1.13.19，与写入条数一致
```

写入 3 条 → 还原 3 条，且还原后 `RN_STATE` 被正常清空（这是正确行为）。

### 4.3 RN_STATE 不再被每轮清空 / 不再每分钟刷降权

- `rayneo_demote_batch` 累计 **792**，最后一条在 **14:51:47**（旧版），**部署后无新增**
- 部署后 `RN_STATE` 为空是**正确门控**，不是修复失效，实测原因：
  - `oom_score_adj=653`（纯后台 cached，未达 300 判活阈）
  - `memo_threads=1`（全天智记 VAD 线程存在）→ 按设计「语音优先，不降权」
  - `bypass=OFF`（未走旁路）
- 若 VAD 不存在且眼镜非活跃，会正常降权并在切前台时 `restored>0`（4.2 已证）

## 六、🔴 新发现 P0：FR-4「CPU 毒瘤检测」自 v1.9.9 起完全失效

`snapshot_app_pids()`（cpu_guard.sh）有两个叠加缺陷：

1. awk 里 **`pid` 从未被赋值**（`FNR==1` 只清空，之后没有取 pid 的语句）
2. 依赖 `/proc/<pid>/status` **末尾的空行**做分隔，而实际 status 文件末尾没有空行

任一都足以让输出恒为空。真机实测：

```
original snapshot_app_pids -> lines=0
单次 awk 扫全部 stat       -> 990 行 / 85ms（说明不是权限或路径问题）
日志：cpu_scan=1349 次，cpu_rogue_intervene=0 次
```

**含义**：`scan_cpu_rogue` 的主循环从未执行过。面板上的「毒瘤降权 0」是**从未扫描**，
不是「没有毒瘤」。FR-4 是模块四大功能之一，等于长期空转。

实测可行的修法（已验证产出，非推测）：

- `FNR==1` 用 `split(FILENAME,…)` 取 pid，`/^Uid:/` 行直接判断 `$2+0 >= 10000`
  → 95 个进程 / 158ms（不依赖末尾空行）
- ticks 改为**单次 awk 扫全部 `/proc/*/stat`** → 990 行 / 85ms
  （替代逐 pid `cpu_ticks_of`：95 次 × 16ms ≈ 1.5s）

**本版未修**：它要改 `take_ticks_snapshot` / `scan_cpu_rogue` 的数据结构，与本次 9 项修复
混在一起将无法归因。建议单独一版（v1.13.20）处理，预计总耗时 158+85+60 ≈ 300ms，
即「恢复功能且不显著变慢」。

## 九、部署脚本自身的一个注意点

`module.prop` 在设备上的 md5 会**随 `update_module_desc` 动态改写 description 而变化**
（部署时 `4757d682` → 运行后 `3553b4b6`，`version`/`versionCode` 不变）。
因此**不能用整文件 md5 作为「部署成功」的判据**；再部署时应只校验
`version=v1.13.19` / `versionCode=59` 两个字段。
