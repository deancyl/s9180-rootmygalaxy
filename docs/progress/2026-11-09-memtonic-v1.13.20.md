## 二、关键缺陷根因与修复方案

### 1. 攻克历史遗留 P0：FR-4「CPU 毒瘤检测」全面恢复
- **缺陷表现**：自 v1.9.9 以来，面板「毒瘤降权 0」并非系统没有毒瘤，而是 `snapshot_app_pids` 输出恒为空，导致 `scan_cpu_rogue` 外层循环从未执行，1349 次扫描 0 次干预。
- **根因分析**：
  1. `snapshot_app_pids` 的 awk 实现中，`FNR==1 { pid=""; uid=""; }` 从未给 `pid` 变量赋值。
  2. 依赖 `/proc/<pid>/status` 尾部的空行 `^$` 触发 print，但内核 status 文件末尾无空行。
- **修复与重构**：
  - `snapshot_app_pids` 改为：`FNR==1 { split(FILENAME, p, "/"); pid=p[3] }`，匹配到 `^Uid:` 且 `$2 >= 10000` 时输出 `pid` 并立即 `nextfile`，实测仅耗时 **80ms**。
  - 新增 `snapshot_app_ticks()`：单次 awk 扫描 `status`，仅对 `Uid >= 10000` 的应用通过 `getline` 提取 `stat` 的 `utime+stime`，消除逐进程调用 `cpu_ticks_of`（95 次 fork ≈ 1700ms 严重拥堵）的瓶颈，1 次 fork **90ms 批量完成**。

### 2. 核心辅助函数全链路零 fork 化与一级缓存
- **`pkg_of()` 零 fork 化**（`mt_lib.sh`）：原本每次调用启动 `strings | head | cut`（3 次 fork ≈ 15ms），改用 `mksh` 内建 `IFS= read -r` 读 `/proc/<pid>/cmdline`，并于 `cpu_guard.sh` 中对 `_pkg_${pid}` 引入一级包名缓存，避免每轮重复解析。
- **`is_in_top_app_cgroup()` 零 fork 化**（`mt_lib.sh`）：由 `$(cat /proc/$1/cpuset)` 替换为内建 `read`，零子 shell。
- **`nice_of()` 零子 shell**（`mt_lib.sh`）：同步设置 `_nice_val` 变量，内部调用免除 `$(nice_of)` 命令替换子 shell。
- **`rayneo_governor` 死条目清洗**（`cpu_guard.sh`）：由原本每轮 2400+ 次 Shell read 读 60 行文件重构为单次 awk 快速过滤，清洗耗时由 **200ms 骤降至 5ms**。

### 3. 作用域与 KernelSU 规范修复
- **`RAYNEO_PKG` 作用域修复**（`mt_lib.sh`）：包名常量上移至 `mt_lib.sh` 全局常量区，修复 `restore_all_on_exit` 无法读取雷鸟 PID 导致 stop/uninstall 100% 跳过雷鸟线程还原的缺陷。
- **补齐 `KSU_MODULE` 环境变量**（`mt_lib.sh`）：`update_module_desc` 调用 `ksud module config set` 时显式注入 `KSU_MODULE=rmg_memtonic`，确保手动 Shell 与 WebUI 刷新时卡片覆盖层设置成功。
- **消除硬编码版本**：`memtonic.sh` 与 `fluency_shield.sh` 启动日志中的 `ver=1.13.18` 改为动态 `${MT_VERSION#v}`；同步更新 `fluency_shield.sh` 头部版本至 `v1.13.20`。
- **清理调试残留**：移除发布包内的 `.bak-1319-pre/`、`.t/` 目录与 `scripts/zz_probe.sh`；移除 `cpu_guard.sh` 内重复的 `RAYNEO_PKG`。

### 4. 深度审查收尾修复（WebUI 权限与 PID 复用缓存安全）
- **KernelSU WebUI 权限隔离规范**（`customize.sh`）：移除 `set_perm_recursive "$PM" 0 0 0755 0644`，仅对 `scripts/` 执行递归赋权，对根目录各脚本（0755）和声明文件（0644）逐一赋权，**严格遵循官方规范，绝不触碰 `webroot/` 目录及其 SELinux 标签**。
- **PID 复用与活跃换皮缓存污染防御**（`cpu_guard.sh`）：
  - 当 `delta < 0`（ticks 回退）时，显式 `unset` 该 PID 的旧状态与包名缓存 `_pkg_${pid}`；
  - 对活跃进程（`delta > 0`）实时通过 `pkg_of` 校验最新包名；当检测到包名漂移（PID 被新进程复用换皮）时立即清空旧状态并重新初始化；
  - 死线程清理循环中补齐 `unset _pkg_${tid}`，杜绝历史包名变量无限泄漏。
- **pkg_of NUL 字节截断与 ash 兼容性重构**（`mt_lib.sh`）：改用 `read -r -d ''` 精准截断 `/proc/<pid>/cmdline` 首段参数，彻底消除多参数连缀导致包名提取异常的隐患，并在不支持 `-d` 时保留零 fork fallback。
- **冗余启动全盘扫描剥离**（`cpu_guard.sh`）：移除 L806-807 无用的 `snapshot_app_pids` 调用，直接调用 `take_ticks_snapshot` 一步到位。
